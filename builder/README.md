# builder — сборка базы подсказок (только у автора)

Эта папка **не попадает в репозиторий** (закрыта в `.gitignore` приложения) и не трогается
автообновлением. Пользователи получают только готовую базу `..\base\hints.db`.

```
builder\
├── data\checks\     выгрузки JSON проверок (исходные данные — не публикуются)
├── precompute.py    сборка базы
├── build.bat        собрать базу (свой venv: numpy, scikit-learn)
├── publish.py/.bat  собрать → поднять версию → commit и push
├── requirements.txt зависимости сборки
└── launchers\       универсальный run_app.bat (как в Toolbox ARM)
```

## Обычный цикл
1. Положить новые JSON в `data\checks\`.
2. `build.bat` — собрать базу. Проверить результат: `..\start.bat` (приложение сразу видит новую базу).
3. `publish.bat --no-build` — поднять версию и отправить в Bitbucket
   (или сразу `publish.bat` — соберёт и выпустит одним шагом).

## Параметры сборки
Основной способ — `builder.ipynb`, шаг 0. Модель для тегов и объяснений задаётся одной строкой:

| `LLM` | что будет |
|---|---|
| `"api:GigaChat-2"` | по API: адрес из `GIGACHAT_API_URL`, токен из `JPY_API_TOKEN` |
| `"api:GigaChat-2-Max"` | другая модель того же API (шаг 3а показывает доступные) |
| `"ollama:qwen2.5:7b"` | локальная Ollama |
| `None` | без модели: теги по словарю `TAXONOMY` |

Ответы модели кэшируются в `cache\llm_cache.json` (ключ — модель + текст запроса): повторная сборка
обращается к API только для новых или изменённых проверок; `LLM_CACHE = False` — выключить.
Если запрос не удался (после 3 повторов при 429/5xx), для этого места берётся вариант без модели;
сводка «запросов / из кэша / ошибок / токенов» печатается после шагов 4 и 5.

То же из командной строки: `python precompute.py --llm api:GigaChat-2 [--no-cache]`;
`--emb intfloat/multilingual-e5-base` — нейросетевое сходство (нужен `sentence-transformers`);
`--dedup 0.4` — порог склейки задач; `--src`, `--out` — другие пути.
Остальные настройки (TAXONOMY, веса, пороги) — в шаге 2 тетрадки / в начале `precompute.py`.

## Что в базе
Таблицы `checks`, `similar`, `hints` и `meta` (дата сборки, число проверок, параметры,
`schema_version`). Приложение показывает дату базы внизу слева и откажется открывать базу
неизвестного формата — если поменяете структуру таблиц, поднимите `SCHEMA_VERSION`
в `precompute.py` и поддержите новый формат в `app.py`.

## Как считается
- «Суть» проверки: название + задача программы + метрики + основания + тексты гипотез и задач.
  По ней ставятся теги методики (`TAXONOMY`) и считается текстовая близость.
- Похожесть = 0.6 × совпадение тегов + 0.4 × близость текстов. Неоткрытые проверки (без задач)
  не служат источниками; для них сходство считается по описанию программы.
- Подсказка = задача из похожей проверки. Одинаковые задачи из разных проверок объединяются.
  Вес = сумма похожести источников; задачи, где нарушение подтвердилось, ×1.5.
- «Есть в программе» — у текущей проверки уже есть похожая задача.
- «Типовые» (акт, хронология и т.п.) — по шаблонам `TYPICAL_PATTERNS` или если задача есть
  в ≥50% проверок; показываются свёрнутыми внизу.
- Настройки: `SIM_TOP_K`, `SIM_MIN`, `W_TAGS`/`W_TEXT`, `CONFIRMED_BOOST`, `TYPICAL_*`, `--dedup`.
